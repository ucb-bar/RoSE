# IsaacLab RiskyBird RoSE environment (`IsaacRiskyBirdMPCEnv-v0`)

A copy of the Isaac Crazyflie env (`envs/isaac_crazyflie/`, the golden reference, left
unchanged) that flies the **RiskyBird** airframe instead of the Bitcraze `cf2x`. It keeps the
**exact same RoSE contract**, so the *unchanged* Zephyr guest (`samples/rose/drone_control`, a
TinyMPC controller) and the *unchanged* loop wiring drive it; only the `gym_env` id differs.
`IsaacRiskyBirdSensorEnv-v0` and `IsaacRiskyBirdMultiSensorEnv-v0` are the matching copies of
the Crazyflie sensor envs and inherit the airframe from this one.

```
Isaac Sim RiskyBird --full 12-DoF state--> RoSE bridge --> Zephyr TinyMPC controller
        ^                                                            |
        +----------- 4 normalized thrusts (per rotor) <-- RoSE bridge <-+
```

- **State served** (reqrsp, 12×f32, target-relative): `[x,y,z, r1,r2,r3, vx,vy,vz, dphi,dtheta,dpsi]`,
  Rodrigues attitude — byte-identical layout to the PyBullet MPC env.
- **Control consumed** (action-latch, 4×f32): normalized per-motor thrusts around the 0.583
  hover point, applied as **per-rotor z-forces at the 4 propeller bodies** (`m1..m4_prop` =
  FR, RR, RL, FL), plus the summed propeller-drag yaw reaction on `body`.

## The airframe

| What | Where |
|---|---|
| Model | `assets/`: the scad RiskyBird v0.1.0 export, vendored unchanged (`assets/SOURCE.txt`) |
| Isaac layout | `assets/riskybird_rose.urdf`, generated by `assets/make_rose_urdf.py`: root link `body`, four 0.1 g prop links on continuous +z joints; the assembly keeps the scad mass (58.5 g), CoM and inertia. Converted to USD on first use, cached in `<tmp>/isaaclab-<uid>/riskybird_usd` |
| Constants | `airframe.py`: hover command, thrust scale, drag ratio, spin signs, sensor poses |

Status of the numbers (see `assets/manifest.json`): mass is documented; CoM and inertia are
inferred from a component model. **Placeholders** until the motors and props are
characterized: the thrust scale (`MAX_THRUST_N`, set so hover sits at the same 0.583 command as
the CF2X model, thrust-to-weight 1.72) and the drag ratio (`KM_OVER_KF`, CF2X value). The spin
signs (`SPIN_SIGN` = -,+,-,+ for FR, RR, RL, FL) come from the scad/dronesim model and are not
yet checked on the real drone; they match the gym-pybullet-drones convention the
`drone_control` TinyMPC was tuned against. The FPV camera defaults to the PCB camera position.

## Requirements

Needs the Isaac Sim toolchain (Isaac Sim 5.1 + IsaacLab 2.3.x) and its URDF importer
extension (`isaacsim.asset.importer.urdf`, fetched by Kit on first use). The env is imported
**lazily** (string entry_point), so the synchronizer stays dependency-light unless this env is
actually `gym.make()`d.

> **Full path-concrete flow (Spike co-sim + video rendering): [`docs/ROSE_ISAAC_COSIM_FLOW.md`](../../../../docs/ROSE_ISAAC_COSIM_FLOW.md).**

## Run (Spike path)

Point the deploy config at this env and use the 1 GHz timing (the setting that hovers):

```yaml
# deploy/config/config_deploy_gym.yaml
gym_env: 'IsaacRiskyBirdMPCEnv-v0'
firesim_freq: 1_000_000_000     # 1 GHz modeled SoC
firesim_step: 20_000_000        # 20M cyc / 1e9 = 0.02 s = 50 Hz => 1 Isaac step / SoC step
max_sim_time: 3.0
```

```bash
# Terminal 1 — synchronizer (Isaac Sim boots in-process; ~1 min first launch)
cd deploy/hephaestus
ROSE_DIR=$(git rev-parse --show-toplevel) \
  <isaaclab-python> run_sync_only.py   # waits: "listening on localhost:10001..."

# Terminal 2 — Spike lockstep bridge with the TinyMPC guest
soc/src/main/cc/rose_spike/build.sh                          # once (-> soc/sim/rose_spike_sim)
soc/sim/run_spike_rose_lockstep.sh \
    soc/sim/zephyr_rose_builds/drone_control/zephyr/zephyr.elf 1
```

Set `ROSE_ENV_DEBUG=1` for the per-step `[isaac-rb]` trajectory print.

## Status (2026-10-21)

- **Airframe checks out in Isaac:** links `body`, `m1..m4_prop` at (±0.0325, ±0.0325, 0.0185)
  in FR, RR, RL, FL order; PhysX mass 0.0585 kg; hover = 0.1435 N/prop = command 0.583.
  Open loop at the hover command it rolls off slowly, as the 25 µm CoM offset predicts.
- **Closed loop with the unchanged `drone_control` guest (Spike, 1 GHz): does NOT hover yet.**
  It climbs to the 1 m setpoint in 0.5 s, then the yaw rate oscillates with growing amplitude
  (sign flips every ~3 control steps) and the run diverges by ~1 s. Cause: the guest's TinyMPC
  model (`quadrotor_50hz_params_constrained.hpp`) has a yaw-rate input row of
  `[+0.39, -0.14, -0.56, +0.31]` per unit command per step, while this plant's real
  propeller-drag yaw is ±2.8 with signs -,+,-,+. The model's thrust and roll/pitch rows are
  close to RiskyBird's (z 0.084 vs 0.084; roll/pitch 5.5-6.1 vs 7.1). The Crazyflie env avoids
  the same failure only through its `_SPIN_SIGN` choice. **Next:** generate TinyMPC problem data
  from RiskyBird's own linearized model and fly it with a RiskyBird guest variant.

## Logging: ground-truth trajectory + camera video

The wire and the log are separate channels (see the repo-wide logging note): `obs` carries
only what the SoC consumes; the **ground truth** (absolute world pose/velocity, per-rotor
forces, target, sim time) is returned in the gym `info` dict, which is never serialized.

- **Trajectory CSV + plot.** Set `traj_csv` (or `$ROSE_TRAJ_CSV`) and the env records the
  ground truth every control step. Render it with:
  ```bash
  # during the run:  ROSE_TRAJ_CSV=/tmp/traj.csv on the synchronizer process
  python envs/isaac_riskybird/plot_trajectory.py /tmp/traj.csv          # -> /tmp/traj.png
  ```
  The figure has the 3D path, altitude-vs-setpoint, horizontal drift, and per-rotor thrust.
  (The plotter is env-agnostic — any drone env that writes the same CSV columns works.)

- **Camera video.** Set `camera: true` (or `$ROSE_ISAAC_CAMERA=1`). The env adds an
  offscreen chase camera that keeps the drone framed; `render()` returns an `(H,W,3)`
  uint8 RGB frame each step (assemble frames into a video, e.g. via `imageio.mimsave`, or
  let `GymLogger.save_video` do it). Cameras must be enabled at Isaac boot, so this is a
  constructor-time flag, not a runtime toggle, and it is **much** slower than the headless
  no-camera path — leave it off for timing runs.

## Key knobs (`gym_kwargs`)

| kwarg | default | meaning |
|---|---|---|
| `ctrl_freq` | 50 | control rate (must match the TinyMPC problem data) |
| `phys_freq` | 100 | physics rate; `decimation = phys_freq // ctrl_freq` sub-steps per control tick |
| `headless` | true | boot Isaac Sim without a GUI |
| `target` | `[0,0,1]` | hover setpoint (state is served target-relative) |
| `start_height` | 0.5 | reset altitude |
| `traj_csv` | `$ROSE_TRAJ_CSV` | path to write the ground-truth trajectory CSV (off if unset) |
| `camera` | `$ROSE_ISAAC_CAMERA` | add the offscreen chase camera so `render()` returns RGB |
| `camera_res` / `camera_focal` | `(640,480)` / `35` | frame size / lens (higher focal = tighter framing) |
| `camera_follow` / `camera_offset` | `true` / `(0.45,0.45,0.18)` | chase the drone; eye = pos+offset |
| `log_dir` | `<tmp>/isaaclab-<uid>/logs` | per-user log dir (avoids the shared `/tmp/isaaclab` owner clash) |
